# 验证与人工验收

本文件是可重复执行的验收清单，不是已通过测试的声明。请在测试记录中填写实际系统、版本、日期和结果。Windows 自动冒烟检查也不能代替真实桌面点按验收。

当前版本为 0.2.2 早期预览。本次 Windows x64 自动验证结果见 [验证记录](VALIDATION-0.2.2.md)。下列真实鼠标、键盘、第三方应用及多 DPI 场景仍按实际执行结果记录，不应由自动检查代替。

## 自动检查

在任何支持 .NET 10 SDK 的环境中：

```powershell
dotnet run --project tests/CloseMeansExit.Tests -c Release
dotnet build src/CloseMeansExit.Windows -c Release
```

在 Windows 中，另运行：

```powershell
dotnet run --project src/CloseMeansExit.Windows -c Release -- --smoke-test
```

策略测试应覆盖时间边界、规则变更、PID / 启动时间 / 路径变化、普通消失、自绘规则、窗口重现和不可靠枚举。冒烟模式应在非交互方式下退出，成功返回 `0`，失败返回非零状态。CI 在 Windows x64 上运行冒烟检查；ARM64 构建产物需要 ARM64 实机复验。

## 交互提醒演示

在 Windows 上运行合成演示：

```powershell
dotnet run --project src/CloseMeansExit.Windows -c Release -- --notification-demo
# 或使用便携程序
.\CloseMeansExit.exe --notification-demo
```

此入口仅显示演示卡片，不检测 / 结束真实进程，不保存设置。程序名、路径和工作集是合成数据，可先验证：

- 卡片出现在工作区右下角，不被任务栏遮挡；不同 DPI 下程序名、完整路径、工作集 MB 与两个按钮可读、可操作。
- 显示卡片时，原来正在输入的窗口仍有焦点，可以继续输入。
- “加入黑名单”和“暂不处理”均能响应；演示退出后原配置没有变化。
- 弱窗口消失提示的“兼容自绘关闭按钮（高级）”默认不勾选，只有主动选择才写入新规则；重新启用旧规则保留原有高级选项。
- 演示只验证呈现和按钮交互；真实持久化、重复提醒与进程结束行为需按下一节另外验证。

## 准备

1. 使用可丢弃的数据和测试应用，先不要给日常编辑器加入规则。
2. 打开任务管理器的“详细信息”，记录每次测试的 PID；不要只根据名称判断是否结束了正确实例。
3. 启动工具，确认没有既存规则，或先禁用旧规则。备份配置时保留原文件，避免覆盖日常规则。
4. 标准窗口可用系统记事本辅助验证输入，但其版本可能有多进程 / 多标签行为。模拟“关闭后隐藏到托盘”时，应使用明确实现 `FormClosing` 取消并 `Hide()` 的独立 WinForms 测试程序，并保持消息循环运行。
5. 准备一个可开第二个窗口、弹出保存确认框、选择最小化和托盘隐藏的测试程序。不要把关闭行为不明的第三方软件当作唯一测试基准。

## 基本安全行为

| 操作 / 前提 | 应当观察到的结果 |
| --- | --- |
| 无规则，测试程序标准点叉后隐藏 | 等待期后出现右下角交互卡片，显示正确 `.exe` 名字 / 路径 / 工作集 MB，原进程继续运行 |
| 在卡片上选择“加入黑名单” | 成功保存完整路径和规则；本次刚发现的进程继续运行；重启工具后规则仍存在 |
| 在卡片上选择“暂不处理”，再重新显示并关闭应用 | 不添加规则；下一次关闭后可以再次提醒 |
| 已有规则，重新打开测试窗口后点叉隐藏 | 满足至少 3 秒等待及持续隐藏条件后，只结束对应实例，记录日志且不再次弹出询问 |
| 两个不同应用在 30 秒内接连隐藏 | 两条提醒均进入队列，依次处理，不因全局时间限流丢失第二个应用 |
| 提醒显示时暂停监测 | 当前卡片关闭、待处理队列清空，恢复后不重放旧提醒 |
| 已有规则，应用自然正常退出 | 不补做无意义的结束，不操作新实例 |
| 点击最小化按钮 | 最小化窗口仍被视为存在，进程保留 |
| 手动最小化到托盘，没有确认点叉意图 | 可提醒疑似候选，文字说明“窗口消失后仍在运行”，不能声称已检测到点叉，不自动结束 |
| 打开两个独立窗口，仅关闭其中一个 | 仍有窗口的进程保留 |
| 点叉后弹出保存 / 取消对话框 | 对话框可见期间保留进程；取消后继续正常使用 |
| 点叉隐藏后，等待期间重新显示窗口 | 取消此次结束，不能稍后继续沿用旧点击 |
| 等待期间暂停监测或禁用 / 删除规则 | 取消此次结束；恢复不能重放旧操作 |
| 长时间保留一个可见窗口，再隐藏 | 旧的关闭事件到期，不能几十秒后意外结束 |
| 同路径启动两个独立实例，只关闭一个 | 不结束另一个实例 |
| 拖出关闭按钮后松开鼠标 | 不被认作有效点叉 |
| `Alt+F4` 关闭已有规则的测试窗口 | 与标准点叉采用相同等待和窗口检查 |
| 只按 `F4` 或在非目标窗口按键 | 不产生错误的目标关闭意图 |

## 兼容性与权限

| 场景 | 验收要求 |
| --- | --- |
| 自绘标题栏，兼容模式未启用 | 不能仅凭右上角位置强制结束；可记录疑似候选 |
| 自绘兼容模式明确启用 | 用实际关闭按钮验证；继续复验最小化、最大化和菜单，避免区域重叠 |
| DPI 100%、150%、200%，双屏不同 DPI | 坐标正确；移动屏幕后仍正确识别关闭区域 |
| 最大化、恢复、窄窗口、右到左布局 | 无错误结束；不支持的布局记录限制 |
| 测试应用以管理员权限运行，工具普通权限 | 访问失败时跳过并记录原因，不自动提权 |
| 自身路径或 Windows 目录程序 | 不能加入可执行的结束规则 |
| 目标退出后 PID 被系统复用 | 身份重验证拒绝新进程；此项以自动模拟测试为主要证据 |
| 无法读取启动时间 / 路径或枚举失败 | 保守取消，日志说明失败 |
| 持续快速打开关闭窗口 | 不对同一次关闭重复执行，不阻塞鼠标输入 |

## 子进程与后台服务

“包含子进程”默认关闭，只应处理窗口所属进程。手动启用该选项时，使用自制、可丢弃的父子进程测试程序验证：

- 子进程有可见窗口或对话框时，不能因关闭父窗口就误杀它。
- 没有交互窗口的已确认子进程，只有身份和关系验证通过后才允许结束。
- 同名、同路径但不属于此树的独立进程必须保留。
- 退出后重新启动的新 PID 不应受到旧关闭事件影响。
- 服务 / 守护进程把应用重新拉起时，工具不循环追杀，也不修改服务配置。

## 托盘与持久化

- 四个页面显示为“发现记录”“黑名单”“当前窗口”“运行日志”。
- 关闭管理窗口会隐藏到托盘并显示说明气泡，之后仍能从托盘重新打开；托盘“退出工具”才完全退出。
- 暂停 / 恢复状态明确，恢复后不重放待执行的旧操作。
- 提醒为带“加入黑名单 / 暂不处理”按钮的应用内交互卡片，不能用没有这两个操作的普通系统气泡替代。
- 重启工具后规则开关、完整路径和高级选项保持一致。
- 目标应用更新或移动目录导致完整 `.exe` 路径变化后，旧规则不匹配新路径，需要重新选择主程序。
- 配置缺失时使用默认值；配置损坏时保留损坏副本并提示，不能悄悄丢弃规则。
- 开机启动默认关闭；开启再关闭后不遗留启动项。移动便携程序目录后重新验证启动路径。
- 不生成外部网络请求；运行日志位于 `%LOCALAPPDATA%\CloseMeansExit\activity.log`，记录应用名字与事件，不保存窗口标题。
- 从完整解压的发布 ZIP 启动，分别在 x64 和 ARM64 设备验证对应构建。
