# 叉掉就退 · CloseMeansExit

让“关闭窗口”重新成为退出应用的明确选择。

> **Beta 测试版 · 0.2.2-beta.1**
>
> 目前仅实现了基本功能，真实应用兼容性和使用体验仍在完善中。欢迎试用、反馈问题和提出建议。

**如果觉得好用，别忘了给项目点个 Star ⭐！**

CloseMeansExit 是一个 Windows 托盘工具：发现窗口消失后仍然存活的应用，会在右下角显示可直接操作的提醒卡片，展示程序名、完整路径和进程工作集；你可以选择“加入黑名单”或“暂不处理”。加入后，下一次确认关闭操作、应用最后一个窗口消失且经过等待，才结束那次关闭对应的进程实例。

0.2.2 基线已在 Windows x64 运行核心测试、原生冒烟检查和专用测试应用的提醒保存链路。真实应用的鼠标点叉、`Alt+F4` 与不同窗口布局仍需人工验收，自动测试通过不能替代兼容性确认。公开 Beta 的构建结果以 GitHub Actions 和对应 Release 为准。

可在仓库的 **Releases** 页面下载 Beta 便携包；首次使用前请阅读下面的说明。[本次 Beta 发布说明](docs/RELEASE-0.2.2-beta.1.md)

## 0.2.2：Steam 与关闭按钮兼容

- Steam 的窗口可能属于 `steamwebhelper.exe`。本版只在完整路径、创建时间及真实父子关系均通过核验时，将它关联到同一安装目录的 `Steam.exe`；不会按名字搜索并结束任意进程。
- 对已启用规则但仅发现窗口消失的应用，会显示“启用关闭按钮兼容”操作，不再只写日志。点击只改变未来规则，不追溯结束当前候选。
- 兼容区域支持报告客户区或标题栏的自绘按钮；快速点击会等待已启动的异步身份核验，并保留实际输入时间。
- Steam 提醒提供明确的“同时结束子进程”选择，默认关闭；该范围可能包括 Steam 启动的游戏。仅结束主程序的规则仍只结束主程序。

旧版的 `steamwebhelper.exe` 规则不会自动扩大为 Steam 主程序规则。使用本版重新打开并关闭 Steam 后，请在提醒中确认目标是 `Steam.exe`；若使用右上角叉号，勾选关闭按钮兼容。是否包含子进程由你选择。首次保存或兼容修复后，均从下一次关闭开始执行。

验证范围见 [0.2.2 验证记录](docs/VALIDATION-0.2.2.md)。

## 0.2.1 修复

- 修复应用带有 Windows 系统辅助子进程时，只读驻留探测被错误取消、导致没有提醒的问题。辅助进程仍参与可见窗口保护；系统程序仍不能成为结束目标。
- 启动监测时立即记录已有窗口，并在核验取消时补充日志，避免失败后只留下启动记录。

验证范围见 [0.2.1 验证记录](docs/VALIDATION-0.2.1.md)。

## 能做什么

- 观察应用窗口，对仍驻留后台的候选应用显示不抢焦点的交互提醒；首次发现不自动结束。
- 提醒卡片展示 `.exe` 名字、完整路径和工作集 MB，直接提供“加入黑名单 / 暂不处理”。多个应用依次排队提醒。
- 按完整 `.exe` 路径管理规则，分别控制是否启用、是否检查并结束子进程、是否启用自绘标题栏兼容区域。
- 识别标准 Windows 关闭按钮和 `Alt+F4`。原始输入照常交给应用，不修改目标应用设置。
- 默认至少等待 3 秒，并要求窗口持续消失至少 1 秒，再重新验证进程身份和规则。
- 托盘暂停、恢复和退出；暂停时关闭当前提醒并清空待处理队列，恢复后不重放旧提醒。开机启动由你手动开启。
- 提供“发现记录”“黑名单”“当前窗口”和“运行日志”四个页面。
- 配置和日志仅保存在本机；日志记录应用名字与事件，不保存窗口标题。应用本身不联网，不收集遥测。

这是一款独立桌面工具，不是浏览器扩展，也不向其他应用注入 DLL。

## 使用

1. 完整解压与你设备对应的 Windows ZIP，运行 `CloseMeansExit.exe`。`win-x64` 适用于常见 Intel / AMD 电脑，`win-arm64` 适用于 Windows ARM 设备。
2. 保持工具运行，正常打开并关闭待观察应用。若进程仍在后台运行，右下角会出现本工具的交互提醒卡片，无需先打开管理窗口。
3. 查看程序名、路径和工作集，选择“加入黑名单”或“暂不处理”。**加入成功会保存规则，从下一次关闭开始生效，不会结束本次刚发现的进程。**“暂不处理”不添加规则，下次关闭仍可提醒。
4. 再次打开已拉黑的应用并点击关闭。满足条件后会自动结束对应实例，只记录结果，不再弹出询问；若还有其他窗口、保存提示或最小化窗口，工具会保留进程。
5. 可在“发现记录”“当前窗口”中手动添加规则；需要临时保留后台任务时，先暂停监测或关闭该应用的规则。

交互提醒使用本工具自带的 WinForms 卡片，包含可点击按钮；候选应用询问不依赖普通系统气泡通知。若只观察到窗口消失、没有确认点叉意图，卡片会说明“窗口消失后仍在运行”，不会把这种情况写成已经检测到点击关闭。

**加入黑名单表示允许在满足条件后强制结束进程。** 这可能中断下载、同步、通话，或丢失尚未保存的内容。优先对已经确定“关闭即隐藏到托盘”的应用逐个启用，避免给编辑器、浏览器和正在处理任务的软件随意添加规则。

工具默认以普通用户权限运行，不会自动请求管理员权限。对管理员应用或受保护进程的访问可能被 Windows 拒绝；此时跳过操作并记录原因。

双击便携包内的 `Preview-Notification.cmd` 可预览右下角提醒及按钮；这是合成演示，不会探测、结束真实进程或保存黑名单。对于仅检测到窗口消失的应用，提醒卡片提供默认关闭的“兼容自绘关闭按钮（高级）”选项，按需勾选后随黑名单保存。

## 判定范围

| 情况 | 行为 |
| --- | --- |
| 未加入黑名单的应用在窗口消失后仍存活 | 记录候选并显示可操作提醒，不自动结束 |
| 点击提醒中的“加入黑名单” | 保存规则，从下一次关闭起生效，不结束当前候选 |
| 点击提醒中的“暂不处理” | 本次不添加规则，下次关闭仍可提醒 |
| 多个应用接连被发现 | 依次排队显示提醒 |
| 已有规则，标准点叉或 `Alt+F4`，最后窗口持续消失 | 等待并验证后结束捕获的进程实例，只记录日志 |
| 最小化、仍有另一个窗口、保存对话框、窗口重新出现 | 不结束此次进程 |
| 只有窗口隐藏 / 销毁，没有确认关闭意图 | 按“窗口消失”说明疑似候选，不自动结束 |
| 等待期间暂停、禁用或删除规则 | 取消此次结束 |
| PID 被复用、启动时间 / 路径改变、枚举不可靠 | 取消此次结束 |
| 同一路径有多个独立实例 | 不按名称批量结束，只操作此次捕获的实例 |
| 应用被服务或守护程序重新拉起 | 不追杀新实例 |

“内存”显示进程工作集，仅供比较，不代表可以精确释放的物理内存量。

### 自绘标题栏

部分应用把关闭按钮画在客户区，不提供标准 `HTCLOSE` 命中结果。对这类应用，可针对该规则手动启用兼容模式：把窗口右上角 **48 × 40 个逻辑像素**的区域视为可能的关闭按钮，并按 DPI 缩放。

这是区域判断，不能可靠识别所有皮肤、窗口布局或特殊按钮。默认关闭；开启前请用该应用逐项验证点叉、最小化、最大化和菜单操作。只有该规则明确开启、原进程最后窗口持续消失时，兼容信号才可能触发结束。

### 多进程应用

“包含子进程”默认关闭，只结束拥有被关闭窗口的那个进程。可针对规则选择包含子进程；执行前仍需确认进程身份、父子关系及相关窗口。某些应用会把任务交给服务、其他独立进程或自动重启机制，工具不保证清除它们，也不修改服务、计划任务或目标应用的启动项。

## 配置与退出

配置：`%LOCALAPPDATA%\CloseMeansExit\settings.json`。运行日志：`%LOCALAPPDATA%\CloseMeansExit\activity.log`。规则基于完整 `.exe` 路径且不区分大小写；更新后路径不变的应用继续匹配，更新或搬家导致路径变化时，需要重新选择主程序并添加 / 调整规则。Windows 目录内程序及工具自身不能加入。

关闭管理窗口会隐藏到托盘，并显示明确的气泡提示；要完全退出，请使用托盘菜单“退出工具”。停用某条规则或退出工具即可停止后续自动结束。开启过“开机启动”时，卸载前先取消该选项，再退出并删除解压目录。目标应用自身的设置不会被修改。

## 从源码构建

安装 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)，在仓库根目录运行：

```powershell
dotnet run --project tests/CloseMeansExit.Tests -c Release
dotnet build src/CloseMeansExit.Windows -c Release
```

在 Windows 上启动：

```powershell
dotnet run --project src/CloseMeansExit.Windows -c Release
```

仅预览交互提醒，在 Windows 上运行：

```powershell
dotnet run --project src/CloseMeansExit.Windows -c Release -- --notification-demo
# 或使用解压后的程序
.\CloseMeansExit.exe --notification-demo
```

演示模式使用合成的程序路径和工作集，用于检查位置、焦点、文字和按钮；不检测或结束真实进程，也不保存任何设置。

构建不依赖用户预装 .NET 的便携版本：

```powershell
pwsh ./scripts/publish.ps1 -Runtime win-x64
# ARM 设备版本
pwsh ./scripts/publish.ps1 -Runtime win-arm64
```

输出位于 `artifacts/`，包含自包含单文件程序、说明和许可证。首次启动时 .NET 可能提取随程序附带的原生运行库。未签名的个人项目可能触发 Windows 对未知发布者的提示；发布包附 SHA-256 校验值。

核心策略及其测试可在 Linux / macOS 运行。Windows UI 和原生钩子仅能在 Windows 运行。交叉编译成功不代表已经通过真实桌面交互测试。

## 发布到自己的 GitHub

源码、测试和发布配置可按 MIT 许可证使用。配置、运行日志与本机构建数据不应提交，详见[隐私与发布内容说明](docs/PRIVACY.md)。如需发布到自己的仓库，将下方的 `OWNER` 替换为目标仓库所有者：

```powershell
git init -b main
git add .
git commit -m "Initial CloseMeansExit beta"
git remote add origin https://github.com/OWNER/CloseMeansExit.git
git push -u origin main
git tag v0.2.2-beta.1
git push origin v0.2.2-beta.1
```

源码 ZIP 不含 `.git`，因此首次发布需要初始化仓库。若已经提交或配置远程，跳过对应步骤并保留现有远程。随附的工作流配置在推送和 PR 时测试、构建，在 `v*` 标签时生成 Windows x64 / ARM64 ZIP 与 `SHA256SUMS`，并创建明确标记为 **Pre-release / Beta** 的 GitHub Release。ARM64 构建不代表已通过 ARM64 实机测试。
