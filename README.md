## 工作方式

加入并启用黑名单后，工具会定期检查该完整 `.exe` 路径的运行实例。应用及其子进程没有可见窗口、经过短暂等待且身份核验通过时，自动结束对应后台实例。无需再次点叉，也无需启用自绘关闭兼容。

这同样适用于加入时已经在后台、启动监测前已经隐藏的实例。恢复监测或重新启用规则会重新检查当前状态。未加入黑名单的应用只提供发现记录和确认提醒。

| 情况 | 行为 |
| --- | --- |
| 加入 / 启用规则时应用已在后台 | 自动检查，等待后结束当前后台实例 |
| 已启用规则，之后窗口消失 | 自动处理，无需识别点叉 |
| 启动或恢复工具时已有后台实例 | 重新检查并按规则处理 |
| 应用有其他窗口、最小化窗口或保存提示 | 保留进程 |
| 等待期间窗口重新出现 | 取消本轮操作；以后再次进入后台会重新检查 |
| 等待期间暂停、停用 / 删除 / 修改规则 | 取消本轮操作 |
| PID、创建时间、路径不符或检查失败 | 取消本轮操作 |
| 同一路径多个实例 | 分别核验各实例及其窗口 |
| 未列入黑名单 | 发现驻留后提醒，需主动加入才能自动处理 |

每次自动处理至少等待约三秒，并要求窗口持续隐藏至少一秒；扫描间隔会增加少量延迟。每轮检查有时限，失败会退避后重新检查。应用重新启动的新实例也会按当前规则重新核验，工具不修改应用的服务或启动项。

## 使用

1. 完整解压 ZIP，运行 `CloseMeansExit.exe`。常见 Intel / AMD 电脑选择 `win-x64`，Windows ARM 设备选择 `win-arm64`。无需另装 .NET。
2. 在驻留提醒中选择“加入黑名单”，或通过“黑名单”页面选择应用主程序。
3. 加入成功后，当前及以后的后台实例会自动处理。仍有窗口的应用继续运行。
4. 需要保留后台下载、同步或其他任务时，暂停监测或停用对应规则。

**升级前请检查已有规则：旧的已启用规则也采用自动后台处理行为。** 强制结束可能中断任务或丢失未保存内容。

Steam 的窗口可能属于 WebHelper，发现记录会在完整路径、创建时间和父子关系核验通过后关联到 `Steam.exe`。如果只希望结束主程序，请使用 `Steam.exe` 规则，并停用旧的 `steamwebhelper.exe` 规则。“包含子进程”默认关闭，开启后可能包含 Steam 启动的游戏；即使只结束主程序，子进程的可见窗口仍会阻止执行。

关闭管理窗口会隐藏到托盘；完全退出请用“退出工具”。开机启动默认关闭，可在窗口底部开启。`Preview-Notification.cmd` 只展示合成提醒，不检查或结束真实进程。

## 数据与权限

设置和日志保存在 `%LOCALAPPDATA%\CloseMeansExit`。规则按完整路径匹配，不按同名程序批量结束。程序自身、Windows 系统目录程序及其他会话受保护；访问被拒绝时不会自动提权。

应用不联网、不收集遥测，日志不记录窗口标题。请勿提交本机配置和运行日志，详见 [隐私说明](docs/PRIVACY.md)。

## 构建与验证

需要 .NET 10 SDK。Windows 交互测试仅在 Windows 上运行：

```powershell
dotnet run --project tests/CloseMeansExit.Tests -c Release
dotnet build src/CloseMeansExit.Windows -c Release
dotnet run --project src/CloseMeansExit.Windows -c Release --no-build -- --smoke-test
./scripts/publish.ps1 -Runtime win-x64
```

便携 ZIP 位于 `artifacts`。打包记录包含源码提交、版本和 EXE SHA-256。推送到 `main` 会运行测试和构建；推送 `v*` 标签后，工作流使用对应 `docs/RELEASE-<版本>.md` 发布标记为 Pre-release 的 Beta 下载包及校验文件。

自动测试覆盖策略、进程身份、窗口保护、提醒保存和自动后台处理链路，均使用专用测试夹具。真实应用与 ARM64 实机仍需单独验收，详见 [测试说明](docs/TESTING.md)。旧版验证记录和发布说明仅描述对应历史版本。
